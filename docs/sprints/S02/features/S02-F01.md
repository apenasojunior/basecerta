## 🔍 Análise de Divergências

### 1. Tabela `socios` - CRITICAL 🔥

**Banco Real:**
```sql
-- NÃO possui PRIMARY KEY explícita
-- Possui UNIQUE INDEX: socios_unique_idx (cnpj_basico, identificador_socio)
-- Total colunas: 11
```

**Model Atual (ERRADO):**
```python
class Socio(Base):
    id = Column(Integer, primary_key=True, autoincrement=True)  # ❌ NÃO EXISTE
    cnpj_basico = Column(String(8), ForeignKey(...))
    # ...
```

**Correção Necessária:**
```python
class Socio(Base):
    __table_args__ = (
        UniqueConstraint('cnpj_basico', 'identificador_socio', name='socios_unique_idx'),
        {'schema': 'cnpj', 'extend_existing': True}
    )
    
    # PK Composta (baseada no unique index)
    cnpj_basico = Column(String(8), ForeignKey(...), primary_key=True, index=True)
    identificador_socio = Column(String(1), primary_key=True)
    # Remover completamente: id = Column(...)
```

### 4. ForeignKeys em Tabelas Auxiliares - MEDIUM 🟡

**Problema:**
Tabelas auxiliares (cnaes, naturezas_juridicas, etc) NÃO possuem PKs no banco, mas models declaram `ForeignKey()` para elas.

**Motivo:** Dados podem conter códigos não catalogados pela Receita Federal.

**Solução:**
```python
# ANTES (com FK)
natureza_juridica = Column(String(10), ForeignKey('cnpj.naturezas_juridicas.codigo'))

# DEPOIS (sem FK, apenas relationship)
natureza_juridica = Column(String(10), comment="Código natureza jurídica")

# Manter relationship para ORM
natureza = relationship(
    "NaturezaJuridica",
    primaryjoin="Empresa.natureza_juridica==NaturezaJuridica.codigo",
    foreign_keys="[Empresa.natureza_juridica]",
    lazy="joined"
)
```

## 📝 Notas Importantes

### Por que remover ForeignKeys?

**Contexto:**  
Dados da Receita Federal podem conter códigos não catalogados nas tabelas de domínio. Se mantivermos FKs rígidas, queries falharão.

**Exemplo Real:**
- Empresa com `natureza_juridica = '9999'`
- Tabela `naturezas_juridicas` não tem código 9999
- Com FK: ❌ IntegrityError
- Sem FK: ✅ Retorna dados, JOIN traz NULL na descrição

**Solução:**
- Remover constraints de FK no SQLAlchemy
- Manter `relationship()` para conveniência do ORM
- Usar LEFT JOIN ao invés de INNER JOIN
